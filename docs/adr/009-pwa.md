# ADR-009: PWA via @ducanh2912/next-pwa

**Status:** Accepted  
**Date:** 2026-05-17

## Context

The app must work as an installable PWA on both desktop and mobile. Next.js doesn't ship a PWA solution out of the box. Two libraries were considered: the original `next-pwa` (unmaintained since 2022) and `@ducanh2912/next-pwa` (actively maintained fork, compatible with Next.js 14/15).

## Decision

Use **`@ducanh2912/next-pwa`**. It wraps the Next.js config as a HOC in `next.config.ts`:

```typescript
export default withPWA({
  dest: "public",          // service worker output
  disable: process.env.NODE_ENV === "development",
  cacheOnFrontEndNav: true,
  aggressiveFrontEndNavCaching: true,
  reloadOnOnline: true,
})(nextConfig);
```

PWA is **disabled in development** to avoid service worker caching interfering with hot reload. Enable it only for production builds.

`public/manifest.json` declares the app shell. Two PNG icons (192×512) are required at `public/icons/` and must be generated manually (use any icon generator or Figma).

The `middleware.ts` matcher explicitly excludes `manifest.json` and the `icons/` path to prevent the auth redirect intercepting PWA asset requests.

## Consequences

- **Positive:** The app is installable on iOS (Add to Home Screen) and Android/Desktop via browser install prompt.
- **Positive:** Offline caching of static assets; the app shell loads instantly on repeat visits.
- **Negative:** Service worker caching can serve stale JS after a deploy. `reloadOnOnline: true` mitigates this by reloading when connectivity is restored.
- **Action required before first deploy:** Generate and place `public/icons/icon-192.png` and `public/icons/icon-512.png`. Without these, the PWA install prompt will not appear.
